# Hardware and software on drone?
- Hexacopter Parts: wifi antenna, gps receiver x2/other sensors, cube (flight controller), nvidia jetson orin nano (onboard computer), 360 auto-stabilize gimbal camera
- Object detection (w3): opencv -> YOLO
- Aerial imagery/stitching (w2): opencv but better with opendronemap (currently offline)
- Flight controller (w4):
- Hardware (cube orange+, pixhawk) + firmware (ardupilot, betaflight, px4)
- Keeps drone flying, little autonomy
- Computer gives command through MAVlink and UART serial cable
- Onboard computer, sensors, middleware (w4-6)
- Jetson/pi with Ubuntu
- Main brain, controls FC
- Code (in ROS framework) takes sensor data, processes data (software team), generates fly commands

# What challenges/projects for software team member?
- Prioritize competitions (autonomy missions): time-based waypoint flying, mapping/surveying, object detection/classification/localization, package delivery
- Individual/group research (extra time): GPS-denied navigation/mapping/localization, controller research to make drone fast, swarming
- Example projects:
  - More robust opendronemap (future skill booster)
  - Stitching real time

# State of modern drones?
- Current stack: ardupilot/px4 (flight control), ROS 2, SIDL, GPS waypoint following (developing autonomous targeting), incremental software checks/simulations (robustness/safety)
- BLVOS: beyond visual line of sight (needs FAA policies)

# How to learn drones in 2026?
- AI is good for conceptual knowledge (get basic knowledge/links)
- AI for coding is ok (Claude/Cursor for ROS 2)
  - Double check code
- Merit: learning experience
- Deploying software requires real experience
- Safer to call off test flight
- Workflow:
  - Talk to get conceptual understanding
  - Set goals for projects/track progress
  - AI + fact-checking
  - Ask for help
- Good to learn other subteams
