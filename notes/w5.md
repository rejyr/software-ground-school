# ROS 2
- many different programs talking to each other (different rates, different langauges, different uptimes)
- use ROS 2
- not OS
- libraries on top of OS
# nodes
- program becomes node
- exchanges typed messages
- ecosystem for managing nodes
- framework for letting robot operate
- one node does one job
- talk only topics/services/actions
- nodes discover each other data distribution service
- node discovery as p2p in ROS 2
# topics (sbuscriber)
- publisher broadcasts
- subscribers listen
- radio broadcast
- named and typed
- async
- many2many
- anonymous
- buffered
- ex: image, detections, odometry, battery
- callback: function ROS2 calls for you
- QoS: resend until arrives, message history, volatile (messages after subscribed)
- need compatible settings
# services (request)
- client asks, server answers
- asking question
- defined by .srv file
- one request -> one response
- one server per name
- supposed to be fast
- ex: arm, set_mode, reset_odometry, get_mission
# actions
- client sets goal, server reports progress
- order tracking
- goal result feedback
- not service bc needs progress
