# what is the role of the flight controller (different from onboard computer?)
- FC (orange box)
  - nervous center
  - receives commands from onboard computer/rc controller (external source)
  - processes radio inputs and executes
  - relies on external commands
- Onboard Computer
  - somatic nervous center (brain)
  - high level tasks (computer vision, path planning, autonomy, etc.)

# sensors in flight controller?
- inertial measurement unit (IMU)
- magnetometer (compass)
- barometer (pressure center)
- kalman filter (fuse sensors at different rates)
- gps module (not in orange, use real time kinematic)
- standard rgb camera
- rc controller

# communication protocols
- serial (UART)
  - direct basic communication between 2 devices
  - typically flight controller and onboard computer, gps, telemetry
  - simple two wires: TX (transmit) and RX (receive)
  - each UART has own wires
  - fommon for MAVlink
- CAN (Controller Area Network)
  - like group chat
  - robust multi-device protocol in cars/high-end drones
- MAVLink (Micro Air Vehicle Language)
  - not physical protocol but message format
  - send commands and receive data
  - for communication between flight controller and onboard computer
- DDS (Data Distribution Service)
  - communication of ROS 2 and modern drone systems
  - real-time publish-subscribe messaging between modules
  - direct connection between FC and OC
  - real-time performance
- common setup: MAVLink/DDS
  - MAVLink: ground station over UDP
  - DDS: between FC and OC

# firmware influence FC capabilities
- low level software on FC, not developed by us
- ex. Ardupilot, Betaflight, PX4
- configured to optimize flight characteristics
- different flight modes
- PID controller (proportional-integral-derivative)
  - just I (past): overshoots and oscillates
  - just D (future): measures rate of error change, corrections not perfect, errors accumulate
  - P: adjust properly
- firmwares
  - ardupilot: autonomous, rich features, heaver codebase
  - betaflight: fpv, ultra responsive manual, limited autonomy/gps
  - px4: research platforms and industry standard, clean architecture, slightly steeper learning curve
